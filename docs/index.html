Ch 1What is ECC?

The big picture · Git: what a repository is, git clone

In plain words

Imagine you hired a talented assistant who doesn't yet know your preferences or process. Now imagine someone handed you a giant binder of ready-made “how we do it” cards, specialist helpers, and automatic checklists. Hand it over and your assistant instantly works like a pro.

ECC is that binder — for AI coding assistants. Its tagline is “the harness-native operator system for agentic work.” Just remember: ECC = a big shared toolbox that upgrades AI assistants.

Designer analogy: ECC is like a design system (a Figma library of components, tokens, and rules). Instead of designing every button from scratch, you pull from the library.

How ECC actually does it

ECC is a repository on GitHub. Inside it packs: 63 agents, 249 skills, 79 commands, 34 rule sets, plus hooks, MCP configs, and a memory/learning system. It's free and open-source (MIT) and works across many “harnesses” — the apps that host AI assistants (Claude Code, Cursor, Codex, OpenCode…).

Git in this chapter — what & why

Word of the day: repository (repo). A repository is a project folder that git watches — git remembers every saved version forever. Designers “Save As v1, v2, v3…”; git does that automatically.

To get your own copy of any repo, you clone it:

git clone https://github.com/affaan-m/ECC.git

clone = “download the entire project, history and all, into a new folder.” It's the first step of using almost any project.

ls means “list.” When you build your own toolbox later, clearly named folders are what make it understandable.

Ch 3Skills in Depth

What a skill really is · Git: add + commit

In plain words

A skill is a labeled instruction card you write once. The AI reads only the label of every card all the time, and when a task matches, it pulls out that card by itself. You never say “use the card” — recognition is automatic.

Designer analogy: a well-labeled swatch drawer. You read the tab (“Brand Blues”) and open it when needed. The skill's label is the tab; the card inside is the how-to. ECC ships 249 of these.

How ECC actually does it

A skill is simply a folder with a file called SKILL.md inside. The .md means Markdown (plain text with light formatting). It has two parts:

Part 1 — the label (“frontmatter”), fenced by --- lines:

---
name: api-design
description: Use when designing a new web API — endpoints, naming, versioning.
---

name = what it's called. description = when to use it — this is the line the AI scans to decide whether to grab the card.

Part 2 — the instructions (the “body”), in plain English:

# API Design

When designing an API:
1. Use nouns for resource names, not verbs.
2. Version every endpoint, e.g. /v1/users.
3. Return clear error messages with a code and a message.

That's a complete skill — no programming required to start.

Git in this chapter — what & why

Committing — saving a snapshot. To make a skill part of the project permanently, you commit it:

git add skills/api-design/SKILL.md     # stage: include in next snapshot
git commit -m "Add api-design skill"   # save the snapshot with a message

git add picks which changes go in (like selecting layers before exporting). git commit takes the labeled snapshot. Good messages keep ECC's ~2,000-commit history readable.

Check your understanding

Q1. What two parts does every SKILL.md have?

Show answer(1) Frontmatter — a label with name and description, fenced by ---. (2) Body — the plain-English instructions.

Q2. Which part tells the AI when to use the skill?

Show answerThe description in the frontmatter.

Q3. Do you need to know programming to write a basic skill?

Show answerNo — it's plain-English instructions in a text file.

Hands-on

Draft a skill label for something you do: name: ______ / description: Use when ______. Keep it focused on when.

Ch 4Agents & Commands

Helpers vs. shortcuts · Git: reading history with git log

In plain words

Agent = a specialist you delegate to. The main AI hands a focused job to an agent who works and reports back. Analogy: bringing in a retoucher for one photo.

Command = a shortcut you type, like /plan. Analogy: a keyboard shortcut — nothing happens until you press it.

HelperWho decides to use it?
SkillThe AI, automatically
CommandYou, by typing it
AgentThe AI, by delegating

How ECC actually does it

63 agents (agents/): e.g. code-reviewer, architect, security-reviewer — each narrow in scope so it does one job well. 79 commands (commands/): e.g. /plan, /code-review, /build-fix. ECC is transitioning to “skills-first” — new capability arrives as auto-grabbed skills, with commands kept for backward compatibility.

Git in this chapter — what & why

Reading a project's history with git log. ECC has ~2,000 commits — a story of every change.

git log --oneline

One line per commit (message + ID). Skim it to learn what a project is focused on. On GitHub this is the “commits” page / a file's “History” button. ECC keeps a single main branch.

Check your understanding

Q1. Who triggers an agent, and who triggers a command?

Show answerAn agent is triggered by the AI (delegation). A command is triggered by you (you type it).

Q2. What does “skills-first” mean?

Show answerNew capabilities are added as skills (auto-grabbed) rather than commands you must type.

Q3. What does git log --oneline show?

Show answerA compact, one-line-per-commit list of the project's history so you can skim how it evolved.

Hands-on

On GitHub, open ECC's commits and read the 5 most recent messages. Are recent changes about skills, agents, or hooks?

Ch 5Rules & Hooks

Standards & automation · Git: why config lives in the repo

In plain words

Rules = your non-negotiables, always true. Analogy: “never use pure black for text.” Hooks = automatic actions that fire on an event. Analogy: an export preset that auto-renames files the moment you export.

How ECC actually does it

Rules (rules/) are split into common/ (universal) plus one folder per language (TypeScript, Python, Go…) — 34 sets covering coding standards, security, testing, and git workflows. Hooks (hooks/) fire on tool events: block a bad action (e.g. a stray console.log), auto-format code, or save/restore session state. (Newer ECC auto-loads hooks — don't also declare them manually, or they load twice.)

Git in this chapter — what & why

Config belongs inside the repo so it travels. Anything set up only on your computer is invisible to others; anything committed into the repo goes everywhere the repo goes. That's why ECC ships rules and hooks as files. In Claude Code, committed project config lives in:

.claude/settings.json

If you want it to apply everywhere, commit it. If it lives only on your laptop, it stays there.

Check your understanding

Q1. Difference between a rule and a hook?

Show answerA rule is an always-follow guideline (what must be true). A hook is an automatic action that fires on an event.

Q2. Why does ECC keep rules/hooks as committed files?

Show answerCommitted files travel with the repo, so everyone who clones it gets the same behavior. Local-only settings don't travel.

Hands-on

Write one rule you'd want an AI to always follow, e.g. “Always include descriptive alt text for every image.”

Ch 6MCP, Memory & Continuous Learning

Connecting outside tools · Git: versioning settings

In plain words

MCP = a standard plug for connecting the AI to outside tools (GitHub, databases, deploy platforms). Analogy: Figma plugins that let it talk to Jira or Unsplash. Memory = notes the AI keeps between sessions. Instincts / continuous learning = ECC watches your sessions, spots patterns, and turns them into reusable skills automatically.

How ECC actually does it

MCP configs (mcp-configs/) ship ready-made connections (GitHub, Supabase, Vercel, Context7…). Tip: keep under ~10 enabled per project — each one consumes some of the AI's limited attention (“context window”). Memory uses hooks (Ch 5!) to save/restore context. Instincts: Stop-phase hooks extract patterns at session end and cluster them into new skills, with confidence scoring and evolution tracking. A loop: hooks → memory/instincts → new skills → a better AI.

Git in this chapter — what & why

Versioning your connections (don't hand-configure). ECC keeps MCP connections as committed files because that makes them reproducible (everyone gets the same setup), reviewable (changes show as diffs), and revertable (roll back a bad config). Same lesson as Ch 5: describe it in a file, commit the file.

Check your understanding

Q1. In one line, what is MCP for?

Show answerA standard way to connect the AI to outside tools — like a plugin socket.

Q2. Why keep under ~10 MCPs enabled?

Show answerEach connection consumes some of the AI's limited context window, crowding out the actual work.

Q3. Which earlier block powers ECC's memory?

Show answerHooks — they save context at session end and restore it at the next start.

Hands-on

List two outside tools you'd want connected for design work (Figma, Drive, a font library…) and what you'd ask each to do.

Ch 7Installing ECC

The 3 install paths · Git: clone vs pull

In plain words

Three ways to get ECC, like installing a font: Plugin install (from a built-in store — cleanest), Manual install (download + run installer — full control), Minimal (just the bit you need).

⚠️ ECC's own warning: don't mix install paths. Pick one and stick with it.

How ECC actually does it

Path 1 — Plugin (recommended), inside Claude Code:

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc

Path 2 — Manual (full control):

git clone https://github.com/affaan-m/ECC.git
cd ECC
./install.sh --profile full     # macOS/Linux
.\install.ps1 --profile full    # Windows

Path 3 — Minimal (rules only):

./install.sh --profile minimal --target claude

Git in this chapter — what & why

Two everyday commands you'll use forever:

CommandWhenMeaning
git clone <url>First timeDownload the whole repo
git pullAnytime afterFetch + apply newest changes

You clone once; you pull whenever you want updates. (Path 1's /plugin marketplace add does the clone for you behind the scenes.)

Check your understanding

Q1. Which path is recommended, and what two commands start it?

Show answerThe plugin install: /plugin marketplace add …ECC then /plugin install ecc@ecc.

Q2. Difference between git clone and git pull?

Show answerclone downloads a repo the first time (creates a local copy); pull updates a copy you already have.

Ch 8Build Your Own — Capstone

Make your first skill · Git: branch → commit → push → PR

In plain words

You'll create your own skill — like the 249 in ECC — then walk the full git workflow real contributors use. We'll build a designer's skill: brand-checker, a card telling the AI how to review a design for brand & accessibility basics. You won't break anything — git makes experiments safe and undoable.

Part A — Write the skill

Create this file at skills/brand-checker/SKILL.md:

---
name: brand-checker
description: Use when reviewing a UI design or front-end for brand and accessibility basics.
---

# Brand Checker

When reviewing a design or UI code, check these and report PASS/FIX:

1. Color contrast: body text meets WCAG AA (4.5:1).
2. Never pure black (#000000) for text — use the brand near-black.
3. Headings use the brand display font; body uses the brand text font.
4. Every image has descriptive alt text.
5. Tap targets are at least 44x44px on mobile.
6. Spacing follows an 8px scale (4/8/16/24/32...).

End with a checklist: each item PASS or FIX, with a one-line reason for any FIX.

Swap the fonts/colors for your own brand — that's the whole point.

Part B — The git workflow, step by step

git checkout -b add-brand-checker-skill     # 1. make a safe branch
# 2. create the SKILL.md file above
git add skills/brand-checker/SKILL.md        # 3. stage it
git commit -m "Add brand-checker skill"      # 4. snapshot + message
git push -u origin add-brand-checker-skill   # 5. upload to GitHub

6. Open a Pull Request on GitHub (“Compare & pull request”) — a proposal to add your branch into main, with a review step. This is exactly how ECC accepts contributions.

branch → edit → add → commit → push → pull request → merge

Git summary

CommandWhat it doesWhy
git checkout -b <name>Make + switch to a branchWork safely off main
git add <file>Stage changesChoose what's in the snapshot
git commit -m "…"Save a labeled snapshotRecord change + reason

Check your understanding

Q1. Order these: commit, push, branch, pull request, add.

Show answerbranch → add → commit → push → pull request (edit the file between branch and add).

Q2. Why work on a branch instead of main?

Show answerA branch is a safe parallel workspace; you experiment freely and others review before merging.

Q3. Difference between commit and push?

Show answercommit saves a snapshot locally; push uploads your commits to GitHub.

Hands-on (the real one!)

Ask your assistant: “create the brand-checker skill and commit it.” Congratulations — you've authored a skill exactly like ECC's. 🎉
